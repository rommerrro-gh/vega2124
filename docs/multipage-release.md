# Многостраничная версия — 23 октября 2026

Приложение остаётся одним React-приложением на прежнем домене. Каждый экран имеет URL, поддерживающий прямое открытие и обновление. HTML-маршруты публичны, но данные и действия требуют прежней серверной авторизации.

| Раздел | Основные адреса |
|---|---|
| Дом | `/miniapp/home` |
| Обращения | `/miniapp/cases`, `?tab=common`, `/miniapp/cases/{id}` |
| Создание и совпадения | `/miniapp/new`, `/miniapp/payment`, `/miniapp/similar` |
| Материалы и визиты | `/miniapp/cases/{id}/messages`, `/documents`, `/history`, `/visits`, `/billing` |
| Общая работа | `/miniapp/shared/{id}` |
| События | `/miniapp/events`, `/miniapp/polls/{id}`, `/miniapp/notices/{id}` |
| Сведения о доме | `/miniapp/tariffs`, `/miniapp/passport`, `/miniapp/contacts` |
| Профиль | `/miniapp/profile`, `/houses`, `/roles`, `/settings`, `/notifications`, `/help`, `/about` |
| Диспетчер и специалисты | `/dispatcher/queue`, `/work/queue`; разделы `/work`, `/control`, `/profile` |
| Управление и получатели | Существующие кабинеты `/admin`, `/uk`, `/system`, `/exchange` и их страницы профиля |

Старые `index.html`, `caseId`, приглашения и MAX start-параметры поддерживаются. Явный адрес экрана имеет приоритет перед сохранённым режимом и старым start-параметром. Новые ссылки опросов и публикаций сохраняют выбранный дом; карточка обращения определяет его через авторизованный API.

Нижняя навигация жителя: Дом / Обращения / События / Профиль. Формы подачи и выбор времени обходятся без неё. Для диспетчера и специалиста: Очередь / Работы дома / Контроль / Профиль. У административных кабинетов остаются собственные рабочие операции и переход в профиль. Вход в роль показывает только доступные роли и не выдаёт новых полномочий.

## Что сохраняется

- Категория обязательна для проблемы; «Другое» позволяет описать неизвестную ситуацию. Получателя определяют сотрудники.
- Поиск сравнивает категорию, описание и известное место. Житель подтверждает совпадение. Отказ поиска допускает явную отправку без проверки.
- Общая работа хранится отдельно от частных обращений, файлов, переписки и визитов. Новый публичный DTO не содержит списка соседей, частных документов и служебных назначений даже для жителя, у которого есть дополнительные роли.
- Черновик живёт 24 часа в пределах вкладки, отдельно для пользователя и дома. Незавершённая отправка сохраняет ключ идемпотентности. Файлы после закрытия вкладки выбираются заново; интерфейс предупреждает об этом.
- Фильтры очереди находятся в URL; вкладки запоминают выбранные фильтры. Возврат по истории восстанавливает положение прокрутки. Поиск не перехватывает фокус после каждого символа.
- Обновления личных обращений и подписки дома настраиваются отдельно. Интерактивные ответы бота не отключаются вместе с событийными уведомлениями.

## Серверная часть и данные

V24 добавляет настройки уведомлений и переименовывает известные учебные подписи. MAX-имена не заменяются; ID, дела, документы, назначения, визиты и сроки сохраняются. Повторный сброс базы не выполняется. Будущие сценарии используют те же обычные имена, адреса и названия организаций. Учебное происхождение обозначено в «О приложении».

Подтверждение общей работы учитывает действующих жителей. Отзыв доступа не проставляет согласие за человека. Если все оставшиеся участники уже подтвердили результат, система повторно проверяет незавершённые работы и завершает общую заявку только после прохождения этих проверок.

Входящие MAX-сообщения получают независимые отложенные повторы. In-flight защищён арендой и токеном владельца: второй обработчик не забирает живую обработку, старый владелец не подтверждает повторно выданную доставку. Гарантия доставки остаётся at-least-once; бизнес-идемпотентность сохраняется.

В обычном профиле незаполненные webhook/MinIO-секреты останавливают запуск. Compose по умолчанию привязывает порты к loopback. Секреты и `.env` не включаются в Git.

## Приёмка

1. Собрать frontend из lockfile, пройти форматирование и DOM-тесты, затем `mvn verify`. Redis-проверки включаются `-Dwebhook.redis.port=<порт>`; CI поднимает отдельный Redis.
2. Проверить главную, длинный адрес, обе темы и отсутствие горизонтальной прокрутки на вертикальном экране.
3. Пройти создание → совпадения → присоединение; проверить общий план и отдельные частные материалы. Проверить вариант без совпадений и сбой поиска без потери черновика.
4. Проверить прямую ссылку, обновление, историю и MAX Back; смену дома и роли; сохранение фильтра очереди.
5. Согласовать визит только после выбора и подтверждения. Проверить переписку и файлы в отдельных экранах.
6. Проверить тарифы и основание ставки, вопрос по квитанции, опрос и его результат, контакты, паспорт и настройки уведомлений.
7. Перед выкладкой сохранить исходники, конфигурацию и БД. После миграции проверить целостность, сохранение ID и число существующих записей. При неуспешной проверке вернуть образ, исходники и снимок БД вместе.

Новые домены, AI/OCR, перенос на PostgreSQL и очистка старых демонстрационных сессий в этот релиз не входят.

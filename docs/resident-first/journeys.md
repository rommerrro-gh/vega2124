# Сценарии, экраны и данные жителя

Статус: проект требований этапа 1. Все новые экраны описывают будущее состояние.

## 1. Общие правила интерфейса

- Один дом выбирается автоматически и явно показан. При нескольких домах виден последний выбранный, его легко сменить. Перед отправкой адрес виден в сводке.
- Из профиля берутся идентификатор пользователя и известные сведения. Повторно вводить их не нужно.
- Нет обязательного выбора организации, гарантийности, причины дефекта, вида договора, формулы или нормативного акта.
- Вспомогательные варианты содержат «Другое» и «Не знаю». Ответ не блокирует отправку.
- Сначала короткое описание, затем только необходимые уточнения. Технические классификаторы сотрудника не копируются в форму жителя.
- Фотографии, квитанции и документы необязательны при первичном обращении. Если для проверки понадобятся дополнительные сведения, сотрудник объясняет какие и зачем.
- Система не подставляет выдуманные значения вместо неизвестных. Неоднозначный результат распознавания требует подтверждения.
- Черновик сохраняется при переходе назад, потере связи и ошибке загрузки. Отказ загрузить файл не стирает описание.
- Дополнительные вопросы задаются один раз в общей истории; переключение между ботом и приложением не начинает процесс заново.
- Не показывать чужие адреса, квартиры, счета и персональные документы при поиске или подборе вариантов.
- Кнопки и сообщения имеют понятные текстовые подписи. Цвет не является единственным признаком статуса; формы доступны с клавиатуры и экранного диктора.

## 2. Главный экран

Порядок содержания:

1. Адрес выбранного дома с возможностью сменить его.
2. Блок «Нужен ваш ответ», если есть ожидаемые действия.
3. Основные действия «Сообщить о проблеме», «Вопрос по квитанции».
4. «Мои обращения» с количеством активных и ближайшим ожидаемым действием.
5. «Мой дом»: паспорт, контакты, опросы, документы, действующие ставки и подтверждённые гарантийные сведения.

Допускается общий вход «Написать свой вопрос»: система предлагает направление, но не заставляет жителя правильно классифицировать вопрос. Неопределённое сообщение принимает очередь первичного рассмотрения.

Для неподключённого дома нельзя обещать, что УК уже получает заявки. Отдельно показывается доступный способ подключения или обращения; личные данные других домов не раскрываются.

## 3. Что спрашиваем и откуда берём данные

| Данные | Источник | Если неизвестно |
| --- | --- | --- |
| Пользователь | Проверенный вход MAX | До доступа к личным делам нужен вход; публичная справка может оставаться доступной |
| Дом | Подтверждённый доступ и выбранный контекст | Помощь с подключением; адрес не доказывает право доступа |
| Что произошло / что непонятно | Свободное сообщение жителя | Предлагаем бытовые примеры; хотя бы осмысленное описание нужно для отправки |
| Место проблемы | Слова жителя, доступные безопасные варианты | «Не могу определить»; уточнение берёт на себя сотрудник |
| Дата возникновения | Необязательный ответ жителя | Сохраняем дату обращения отдельно; не выдаём её за дату обнаружения |
| Квартира | Подтверждённая привязка, если есть | Можно сообщить номер для организации осмотра; это не открывает чужие документы |
| УК / поставщик / застройщик / подрядчик | Настройки дома и проверка сотрудника | Первичное рассмотрение; житель не выбирает получателя |
| Гарантийный срок / причина дефекта | Документы и осмотр | Не определено; вопрос всё равно регистрируется |
| Квитанция / фото | Необязательная загрузка | «Сейчас нет под рукой»; можно приложить позднее |
| Период / строка / лицевой счёт | Проверенная привязка или подтверждённые данные документа | Принимаем вопрос без них; уточняем доступным способом |
| Сумма / ставка / объём | Подтверждённые данные документа или сотрудника | Никаких догадок; вывод «недостаточно данных» |
| Право предъявить формальное требование | Проверка полномочий заявителя | Можно сообщить проблему; формальная отправка от имени лица требует отдельной проверки |

## 4. Путь А. Обычная проблема дома

Пример: «В подъезде темно. Не знаю, лампа или проводка».

| Шаг | Житель | Система / сотрудник | Что видно жителю |
| --- | --- | --- | --- |
| A1 | Описывает ситуацию | Сохраняет черновик и контекст | Поле «Что случилось?» |
| A2 | По возможности указывает место, добавляет фото | Предлагает только нужные уточнения | «Где вы это заметили?» и «Не могу определить» |
| A3 | При желании открывает похожее обращение | Показывает безопасную сводку кандидатов | «Похоже, об этом уже сообщили»; можно продолжить своё |
| A4 | Проверяет короткую сводку и отправляет | Регистрирует один раз, назначает очередь | Номер, адрес, описание, «Разберёмся, кто должен помочь» |
| A5 | Получает сообщение при необходимости | Диспетчер классифицирует, назначает исполнителя | Ответственный, следующий шаг и подтверждённый срок либо «Срок уточняется» |
| A6 | Отвечает на результат | Сохраняет ответ и возвращает работу при необходимости | «Стало лучше?» — «Да», «Нет», «Пока не могу проверить» |

Существующее разделение обращения и общей заявки сохраняется. Кандидат не раскрывает личные документы другого участника. Присоединение добровольное; новое обращение не удаляется при объединении.

## 5. Путь Б. Возможный строительный дефект

Пример: «После дождя мокнет стена в подъезде». Первые шаги совпадают с A1–A4. Вопроса «Это гарантия?» нет.

| Шаг | Житель | Система / сотрудник | Что видно жителю |
| --- | --- | --- | --- |
| B1 | Сообщает бытовое наблюдение | Диспетчер оценивает срочность, организует осмотр | «Нужно осмотреть место» |
| B2 | При необходимости выбирает удобное время и подтверждает доступ | Инженер согласует осмотр | Дата, кто придёт, что нужно от жителя |
| B3 | Может добавить наблюдение | Инженер фиксирует дефекты и предварительные причины, готовит акт | Результат осмотра простыми словами и доступный документ |
| B4 | Не ищет договоры подрядчиков | Сотрудник проверяет документы и передаёт требование уполномоченному адресату | Подтверждённая стадия передачи и кто ведёт дело |
| B5 | При необходимости отвечает на понятный запрос | Гарантийная служба принимает решение, назначает обследование или мотивирует отказ | Решение и следующий шаг; отказ не выдаётся за окончательно установленную истину |
| B6 | Согласует доступ для работ | Генподрядчик / исполнитель выполняет задания | Срок, изменения и причины переноса |
| B7 | Сообщает о результате | Инженер проверяет устранение, фиксирует повторный дефект | Итог проверки и возможность «Проблема осталась» |

Параллельность: при необходимости срочные меры и выяснение гарантийной ответственности идут отдельно. Завершение временных мер не закрывает основное дело.

Акт не становится подписанным только из-за создания PDF. Черновик, подписи, возражения, доставка и регистрация фиксируются отдельно. Уполномоченный заявитель и организация определяются до формальной передачи.

При отказе житель может выбрать «Не согласен, прошу проверить» или запросить объяснение. Контакт с другим участником организует сотрудник; пересоздавать обращение не нужно.

## 6. Путь В. Вопрос по квитанции

Пример: «Сумма стала больше, не понимаю почему».

| Шаг | Житель | Система / сотрудник | Что видно жителю |
| --- | --- | --- | --- |
| C1 | Пишет вопрос или выбирает бытовую подсказку | Принимает вопрос без определения причины | «Что вас смущает?» — «Сумма больше», «Непонятная строка», «Другое / не знаю» |
| C2 | По желанию прикладывает документ | Предлагает безопасную привязку и распознавание | «Можно приложить квитанцию. Если её нет — продолжайте» |
| C3 | Проверяет только нужные распознанные поля | Выделяет неуверенные значения; не требует перепечатать документ | Фрагмент документа рядом со значением; «Не могу проверить» |
| C4 | Получает объяснение, если данных достаточно | Сравнивает подтверждённые данные по поддерживаемым правилам | Что изменилось, расчёт и источник; отдельно неизвестное |
| C5 | При необходимости просит разобраться | Автоматически создаёт дело с исходным контекстом или предлагает сотруднику проверить | «Прошу проверить»; причина ошибки и получатель не обязательны |
| C6 | Отвечает на понятные запросы | Сотрудник определяет адресата и проверяет начисление | Кто рассматривает, что проверяет и следующий шаг |
| C7 | Знакомится с итогом | Сохраняет объяснение или подтверждает отражение исправления | Исправленный документ либо обоснованный ответ; «Вопрос остался» |

Плохое распознавание, отсутствие истории, неизвестный поставщик или неподдерживаемая формула переводят к сотруднику без повторного заполнения. Неизвестная причина роста не объявляется ошибкой тарифа.

Общее разъяснение по ставке доступно относящимся к нему жителям. Личные суммы, счета, долги и документы соседям недоступны. Группировка похожих вопросов не объединяет личные документы.

## 7. Единая карточка обращения

Первый экран: бытовое название, адрес, номер, краткая стадия, кто ведёт дело, следующий шаг, срок или честное сообщение об уточнении.

Ниже: действия жителя, история, переписка, доступные документы. Подробности организаций раскрываются по желанию, но не нужны для продолжения.

Примеры:

- «Назначаем осмотр. Выбирать организацию не нужно».
- «УК ведёт обращение. Гарантийная служба получила материалы» — только при подтверждённом получении.
- «Документы подготовлены. Передача ещё не подтверждена».
- «Проверяем, почему изменилось начисление. Сейчас от вас ничего не требуется».

Нельзя использовать «Выполнено» для простой передачи, «Перерасчитано» для обещания исправить и «Решено» для отсутствия ответа.

## 8. Бот и непрерывность пути

Меню: «Сообщить о проблеме», «Вопрос по квитанции», «Мои обращения», «Мой дом», «Помощь».

Диалог повторяет правила форм: текст своими словами, минимум вопросов, фото по желанию, неизвестное допустимо. Есть «Назад», «Продолжить без файла», «Отменить черновик». Кнопки не требуют знать роли организаций.

Переход в мини-приложение открывает нужное дело или черновик. Старое сообщение сверяется с актуальным состоянием. Повторное нажатие не создаёт копию. Ошибка отправки сохраняет ввод и показывает, зарегистрировано ли обращение.

## 9. Исключения и помощь

- Подозрение на срочную опасность: показываем проверенные контакты для выбранного дома и сообщение о необходимости срочной связи; обращение можно сохранить и передать сотруднику. Не утверждаем, что аварийная служба вызвана без подтверждения.
- Маршрут неизвестен: дело остаётся у назначенной очереди первичного рассмотрения, а не возвращается жителю с выбором получателя.
- Организация недоступна: координатор видит сбой и организует дальнейшую обработку; житель видит честный статус.
- Сотрудник отсутствует: срабатывает замещение / служебная эскалация; дело не теряет владельца.
- Нет права на личные сведения: принимаем сам вопрос и предлагаем помощь с подтверждением доступа; не раскрываем данные по указанному номеру квартиры или счёта.
- Житель не может предоставить документ: фиксируем это и предлагаем получить сведения из доступных организации источников либо организовать осмотр.
- Нужна причина переноса или отказа: её вводит сотрудник, а не житель.

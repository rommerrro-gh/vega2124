# Этап 4. Обращения в боте MAX

20 октября 2026 года.

## Что реализовано

- Меню в личном диалоге: сообщение о проблеме, вопрос по квитанции, мои обращения, дом/контакты, помощь. Системное меню команд `/start`, `/new`, `/payment`, `/cases`, `/house`, `/help`, `/cancel` регистрируется отдельной операцией `scripts/max_staging.py register-commands`.
- Обычный текст тоже начинает черновик общего вопроса. Получателя, гарантийность, категорию и техническую причину житель не определяет. При нескольких домах без действующего выбора бот предлагает выбрать знакомый адрес.
- Описание дополняется следующими сообщениями. Фото JPEG/PNG и PDF необязательны: до 5 файлов, каждый до 10 МБ, общий размер черновика до 20 МБ. Неподдерживаемые вложения не считаются принятыми. При ошибке сообщение не меняет прежний черновик; текст/файл из этого сообщения надо прислать снова.
- Перед регистрацией показываются адрес, описание и количество файлов. До нажатия «Отправить обращение» обращение не зарегистрировано. Черновик хранится на сервере 24 часа после последнего изменения; открытие приложения его не редактирует. Его можно продолжить или удалить. При отзыве доступа продолжение блокируется.
- После регистрации используются те же resident_cases, сообщения, документы и права, что в мини-приложении. Старые заявки не преобразуются: они доступны через приложение.
- В чате есть список обращений выбранного дома с постраничным просмотром, состояние, следующий шаг, ответственный, срок по Москве, последнее сообщение и число документов.
- Житель отвечает сотруднику, подтверждает предложенный результат отдельным действием или просит повторную проверку с пояснением/без него. Только автор с действующим доступом может выполнить эти операции. Проверяется ревизия карточки; молчание не закрывает обращение.
- Кнопка приложения передаёт `case_<uuid>` и открывает соответствующую карточку, включая правильный дом. Стартовый параметр не даёт прав: данные загружаются через аутентифицированный API.
- Изменение следующего шага, срока, участника, сообщение или документ от сотрудника ставит уведомление автору в очередь в той же транзакции. Несколько накопившихся изменений объединяются в актуальную карточку. Перед отправкой заново проверяются профиль, принадлежность дому и авторство.
- Только личные диалоги. Группы и каналы не открывают финансовые дела и не создают частные черновики. Адрес сам по себе не подтверждает право доступа.

## Надёжность

Миграция V14 добавляет сессии, временные файлы, устойчивые ключи входящих сообщений и очередь ответов. Ранее потреблённые сообщения старого обработчика повторно не превращаются в обращения. Повторная доставка одного mid не повторяет действие. Изменение данных, ключ сообщения и ответ записываются одной транзакцией. Сетевые ошибки отправки вызывают повтор только отправки, с задержкой до часа. Протокол MAX не предоставляет здесь подтверждённый ключ идемпотентности отправки: при потере ответа сервера MAX возможен повтор самого сообщения бота, но не обращения или действия.

Загрузка медиа выполняется до транзакции SQLite, только по HTTPS с разрешённых доменов MAX, без перенаправлений и без передачи токена. Проверяются ограничения размера и сигнатуры файлов. Медиа недоступного формата/ссылки можно загрузить в приложении. Внешняя ссылка вложения не является способом скачивания документов сервиса: документы выдаются прежним API с проверкой прав.

Ответы отправляются не чаще одного на пользователя за цикл (по умолчанию раз в секунду). Черновики удаляются после истечения срока, доставленные/отменённые ответы — через 30 дней. Ключи обработки сохраняются для защиты от позднего повтора событий. В демопрофиле внешняя отправка отключена.

## Приёмка

1. В личном диалоге `/start` показывает меню. Новый пользователь получает предложение подключить дом через приложение, без самовольного создания членства.
2. Подключённый житель пишет «Мокнет потолок, не знаю откуда». До подтверждения существует только черновик. После подтверждения — одно обращение с тем же текстом, без обязательного места и файлов.
3. Прислать фото/PDF до отправки, проверить его наличие и скачивание в приложении. При повторной доставке mid файл и обращение не дублируются.
4. Диспетчер запрашивает уточнение в приложении. Уведомление содержит нужное действие; ответ в боте появляется в истории и возвращает обращение на рассмотрение.
5. Предложить результат. Подтверждение в чате закрывает его; повторная проверка возвращает в работу. Устаревшая ревизия и кнопка другого обращения не подтверждают результат.
6. Ссылка из карточки бота открывает эту карточку приложения даже при ранее выбранном другом доме. Чужой UUID не открывается.
7. Вопрос по квитанции не раскрывается обычному диспетчеру/соседу/группе. После отзыва доступа ожидающее уведомление отменяется.
8. Остановить доступность MAX API, повторить событие и восстановить сеть: действие выполнено один раз, ответ остаётся в очереди до доставки.

Автоматические сценарии выполняются на отдельных временных базах с подменой MAX API, без сообщений реальным пользователям. Проверка полного взаимодействия в реальном клиенте MAX и независимая пользовательская приёмка учитываются отдельно; автотесты их не заменяют.

## Источники протокола

- [Клавиатура MAX](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard): используются кнопки message и open_app; дополнительная callback-подписка не требуется.
- [Команды бота](https://dev.max.ru/docs-api/use-cases/chatbot-commands): PATCH /me/commands.
- [Параметры запуска приложения](https://dev.max.ru/docs/webapps/introduction): start_param.

Полный гарантийный процесс, реестр тарифов и расчёт начислений остаются следующими этапами.

## Результаты автоматической проверки

Maven verify: 75 тестов, 0 падений, 0 ошибок, 1 пропуск (Redis integration без отдельного Redis). Включены 17 сценариев бота, повторная доставка, ошибки отправки, финансовая изоляция, отзыв доступа, чужое/устаревшее подтверждение и обновление существующего дела V13 → V14.

На отдельном локальном стенде визуально проверен запуск с `WebAppStartParam=case_<uuid>`: сразу открывается нужное обращение с историей, следующим шагом и документами. Реальный клиент MAX в эту проверку не входил.

## Старт, меню и помощь

`/start` и событие `bot_started` знакомят с Пульсом дома и объясняют пользу для жителя. Для нового пользователя отдельно указан способ подключения дома. `/help` и «Помощь» открывают инструкции по подаче, документам, черновикам, статусу, ответу и проверке результата. «Меню» и `/menu` дают короткий выбор действий. Все три экрана сохраняют действующий черновик и кнопку его продолжения.

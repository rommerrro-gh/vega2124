# Общие заявки и обновлённая демонстрация

Вход жителя: «Сообщить о проблеме» и «Вопрос по квитанции». Категория проблемы обязательна в интерфейсе, неизвестная категория — «Другое». Место можно не указывать. Получателя житель не выбирает. Сохранённые старые черновики GENERAL преобразуются в PROBLEM/OTHER. API принимает GENERAL и отсутствие категории для совместимости, преобразуя их в PROBLEM/OTHER.

Поиск учитывает категорию, нормализованный текст и совместимость места. «Другое» ищет по всем категориям. SHARED предлагает присоединение, OWN_SHARED открывает своё обращение. Это детерминированное сравнение, без ИИ и OCR.

У общей заявки одна запись в очереди и общий статус, ответственный и срок следующего шага. Каждый участник имеет собственное обращение с приватными файлами, сообщениями и визитами. Назначенный на общую заявку сотрудник получает необходимый доступ к материалам участников; соседям они не доступны. Финансовые обращения всегда отдельные и требуют отдельного допуска сотрудника.

Сотрудник уточняет публичное описание и категорию, объединяет заявки с причиной или выделяет присоединённое обращение обратно. Каноническое обращение остаётся опорой общей работы: отделять нужно присоединённые обращения. Все действия проверяют актуальную revision и права дома. При объединении сохраняются история, документы, задания и материалы каждого обращения. Перед предложением результата проверяются незавершённые работы всех участников, включая отозванные.

Участник подтверждает результат за себя. Если после объединения у одного жителя несколько обращений об одной проблеме, одного подтверждения достаточно. Общая заявка закрывается после подтверждения всех участников; сообщение одного жителя «проблема осталась» возобновляет общую работу. Автоматического подтверждения по молчанию нет. Отзыв не удаляет историю и не снимает обращения соседей. Если последний участник ушёл, незавершённые работы остаются в очереди сотрудника до завершения или обоснованной отмены.

Главная: осенняя Казань, зелёные акценты, два основных действия, одно актуальное обращение с временной шкалой. При предложенном визите — реальное доступное время и кнопка выбора. Опрос показан компактной строкой, подробности платежей и дома раскрываются отдельно. Новые маршруты экранов не добавлялись.

## Данные и обслуживание

V21 создаёт новые таблицы и безопасные общие оболочки для существующих современных обращений; личный текст старого обращения не публикуется соседям. Миграция не удаляет исходные обращения, не меняет их сроки и не отменяет старые уведомления.

Отдельная явно включаемая команда обслуживания выполняет согласованную очистку старого формата (issues/reports/incidents и зависимые записи), сохраняя современные resident_cases, пользователей, дома, организации и доступы. Демонстрационные дома обновляются отдельно: фиксированный demo-house-1 и активные изолированные guided-demo дома. Их тестовые обращения, голосования, тарифы и связанные записи заменяются согласованным набором сценариев. При обычном запуске обновление не выполняется.

Запуск только при остановленном backend, с резервной копией БД и тома, на отдельной копии БД, без сети и MAX-токена:

```text
java -jar app.jar --server.port=0 
  --demo-scenarios.refresh=true --demo-scenarios.remove-legacy=true 
  --demo-scenarios.exit-after-refresh=true --operations.scheduler-enabled=false
```

Демонстрационный профиль применяется только на demo-стенде. На MAX — профиль по умолчанию. После успешной проверки целостности, внешних ключей, сохранности доступов и современных записей вне демодомов подготовленная БД заменяет рабочую при остановленном backend. Исходная копия хранится для восстановления. Старые объекты файлового хранилища физически не стираются этой командой.

Набор: освещение с предложенным визитом; лифт с тремя участниками; возможный гарантийный дефект окна и работа; уборка с предложенным результатом; повторно открытая проблема двора; отдельный вопрос по начислению воды; два условных учебных тарифа; опрос и плановое отключение. Учебные тарифы явно помечены и не выдаются за действующие.

## Приёмка

- Два жителя сообщают об одном дефекте: одна общая заявка, две приватные истории, один элемент очереди.
- «Другое» находит тот же дефект; несовместимое место не объединяется автоматически.
- Документ или сообщение второго участника недоступны первому; финансовое обращение не попадает в общие заявки.
- Объединение и выделение сохраняют материалы; устаревшая revision и недостаточные права отклоняются.
- Подтверждение первого участника не закрывает заявку за второго; отказ возобновляет работу для всех.
- Отзыв сохраняет соседей; незавершённые работы после последнего отзыва остаются сотруднику.
- Главная показывает предложенный визит, выбор сохраняется, голосование работает; 320px и обе темы читаемы.
- Повторное обновление учебного набора не плодит записи, не затрагивает чужие дома и не создаёт рассылку.

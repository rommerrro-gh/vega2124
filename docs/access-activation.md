# Активация пользователей в MVP

Личность подтверждается подписанными данными MAX. Первый вход создаёт пользователя без ролей. Доступ появляется только после принятия приглашения; приглашение сначала показывает роль, УК, дома, пригласившего и срок действия. Токен хранится в базе как SHA-256 hash и возвращается создателю один раз.

## Цепочка ролей

| Приглашающий | Кого приглашает | Область |
| --- | --- | --- |
| `SYSTEM_ADMIN` | `UK_ADMIN` | Одна УК и выбранные закреплённые за ней дома |
| `UK_ADMIN` | `DISPATCHER` | Один или несколько домов из собственной области |
| `UK_ADMIN` | `HOUSE_ADMIN` | Один дом из собственной области |
| `HOUSE_ADMIN` | `RESIDENT` | Свой дом |

Административные приглашения одноразовые и действуют 72 часа. Приглашение жителя действует 1–30 дней и допускает 1–100 активаций. Роли не наследуются: администратор дома может подавать обращения как житель только при отдельном назначении `RESIDENT`. Один пользователь может иметь несколько назначений.

## Первый системный администратор

1. Настроить `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, публичный HTTPS адрес и открыть mini app из MAX под учётной записью будущего администратора. Первый API запрос создаст пользователя без доступа.
2. На стенде найти его MAX ID: `docker compose run --rm staging-seed --db /app/data/pulse-doma.db users`.
3. Однократно назначить первого администратора: `docker compose run --rm staging-seed --db /app/data/pulse-doma.db system-admin --max-user-id <max_user_id>`.
4. Повторно открыть mini app и перейти в `/system/index.html`. Команда откажется назначать второго системного администратора.

Системный администратор создаёт УК и дом, закрепляет дом за УК, затем создаёт приглашение `UK_ADMIN` с выбранными домами. Администратор УК принимает приглашение, создаёт приглашения диспетчеру и администратору дома. Администратор дома приглашает жителей. При заполненном `MAX_BOT_USERNAME` интерфейс показывает готовую ссылку `https://max.ru/<bot>?startapp=<token>` и кнопку копирования.

## Отзыв и область доступа

Отзыв приглашения запрещает будущие активации; ранее выданная роль остаётся активной. Отзыв роли меняет `access_status` на `REVOKED` и сразу закрывает доступ в API. При приостановке связи дома с УК область соответствующих администраторов УК, диспетчеров и администраторов дома переходит в `SUSPENDED`. Повторное закрепление восстанавливает эти назначения; отозванные роли не восстанавливаются. Дом не может одновременно быть активным в двух УК.

Пользователь не может отозвать собственную роль через административный API. Администратор дома управляет только ролями `RESIDENT` своего дома; роли других администраторов дома отзывает администратор УК.

Существующие до миграции V6 членства сохраняются как активные. Старые приглашения жильцов остаются в `house_invitations` для совместимости с ранее выданными ссылками; новые кабинеты создают приглашения через `access_invitations`.

В локальном профиле `demo` роль `SYSTEM_ADMIN` и `UK_ADMIN` дополнительно назначена демо-администратору, чтобы можно было открыть `/system/index.html` и `/uk/index.html` с `X-Demo-Session: admin`. Это тестовый вход; в обычном профиле требуется подписанная строка MAX.

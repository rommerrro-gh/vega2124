# Приёмка в web MAX — 25–26 октября 2026

Проверка выполнялась через действующий вход владельца проекта в web.max.ru, в мини-приложении, на персональных учебных данных. Подписанные параметры входа и коды приглашений в отчёт не включены. Снимки интерфейса обрезаны до приложения, без списка личных чатов MAX.

## Найдено и исправлено

1. Общий технический осмотр ошибочно переводил служебную заявку в ожидание подтверждения жителя, который не мог ответить в этой карточке. Для общей работы осмотр теперь сразу запланирован, заявка остаётся в работе; личные визиты сохраняют согласование с жителем. Исправлен также генератор учебных осмотров.
2. В списках инженеров и исполнителей отображались не назначенные в обращение сотрудники; сервер отклонял такой выбор. Добавлены отдельные серверные списки назначенных инженеров и исполнителей, описанные в OpenAPI. Проверки полномочий сохранены.
3. После объединения заявок диспетчер оставался на старом адресе карточки, а обновление списка возвращало уже объединённую заявку и ошибку «Общая заявка недоступна». Обновляются выбранная карточка и адрес, новая карточка добавляется в локальный список; при возврате очередь перечитывается. Добавлен DOM-тест реального объединения. Личная карточка, отсутствующая в общей очереди, отдельно загружается по прямому адресу с обычной серверной проверкой доступа; это также проверено DOM-тестом.
4. Переключение вкладок системного администратора сбрасывало выбранную организацию. Контекст сохраняется и не переносится в раздел жителя.
5. После отзыва приглашения оставалась видимой ранее созданная ссылка. При успешном отзыве результат создания очищается в действующих и старых кабинетах.
6. При истечении подписанного входа MAX показывалась техническая инструкция про локальный demo-профиль. Теперь указано, как повторно открыть приложение через бота. Срок авторизации не увеличивался.
7. В личном финансовом обращении показывалась подсказка о материалах участников общей заявки. Общий служебный процесс теперь определяется отдельно.
8. Удалено действие отзыва «моего» обращения из панели сотрудника; действие жителя сохранено. Внешним организациям не предлагается открытие личных материалов участников. Серверные ограничения доступа сохранены.
9. Уточнены подписи срока опроса и доступа жителей; убраны пустые разделители в команде/приглашениях; пустые документы и контроль больше не сообщают об отсутствии назначенных работ.
10. Для координатора, который сам сдавал отчёт исполнителя, добавлено пояснение: его должен принять другой координатор.

## Границы проверки

Это не подтверждение буквального прохождения всех возможных комбинаций:

- Приёмку собственного отчёта и рассмотрение собственного финансового дела система намеренно запрещает. Полный переход с другим координатором, принятие приглашения другим человеком, замещение и межпользовательская изоляция проверяются серверными тестами с разными пользователями. Единственный действующий вход MAX не даёт воспроизвести второго человека вручную.
- Выбор файла через IAB не выдал событие filechooser, а доступ к нативному окну Codex запрещён инструментом. Реальная отправка файла через MAX в этом проходе не подтверждена; проверки вложений на сервере имеются. Ограничение инструмента не обходилось.
- Нативные MAX на iOS/Android недоступны для управления; проверен web MAX в узком вертикальном окне. Фактическая доставка новых сообщений ботом в нативный клиент отдельно не подтверждена.
- Будущий осмотр не выдавался за состоявшийся; публикация акта и окончательное гарантийное решение проверяются автоматическими тестами, а не вымышленным осмотром в текущей сессии.
